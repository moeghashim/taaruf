## Exact external-send race limitation

Convex archive, matching creation, advancement and claims serialize transactionally because they read the same registration documents written by archive. An archive committed before a claim/revalidation prevents that operation. But HTTP email delivery is outside Convex's database transaction: a sender can pass the check, then archive commits, then the provider accepts the email. An already-running/provider-accepted call cannot be canceled by database rollback. Checking immediately before each send narrows but does not eliminate this window. Current notification timestamps are claim/result fields, not a durable transactional outbox or provider cancellation mechanism. Do not claim a zero-post-archive-send guarantee. Strict delivery cutoff would require a serialized delivery/outbox design with explicit in-flight semantics and provider cancellation support; even an outbox alone cannot unsend an accepted email.
